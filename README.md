# jik-lsp

基于 Rust 和 `tower-lsp` 的 Jik 语言服务器，目前支持完整文档同步和保存后诊断。

```sh
cargo build --release
```

启动 `target/release/jik-lsp`，使用标准输入/输出进行 LSP 通信。在编辑器的语言服务器配置中将 `.jik` 文件关联到该程序；初始化选项示例：

```json
{
  "jikPath": "/absolute/path/to/jik",
  "entryPath": "/absolute/path/to/project/main.jik"
}
```

`jikPath` 可省略，默认使用 PATH 中的 `jik`。`entryPath` 可省略，默认检查保存的文件；配置时必须使用绝对路径。两项都会在 initialize 阶段校验一次：显式给出的 `jikPath` 必须存在且可执行（含路径分隔符时按给定路径检查，裸名称在 PATH 中查找），`entryPath` 必须存在；校验失败会让 initialize 返回错误并指明具体路径，而不是等到每次保存才失败。省略 `jikPath` 时不校验，编译器缺失仍会在首次检查时报错，这样未安装编译器的环境也能正常启动。`jik check` 要求有效的程序入口，直接检查独立模块可能报告缺少 `main`。编译器需要自身安装目录中的 `jiklib`，并遵循其 `JIK_PKG_PATH` 设置。

诊断只在保存后运行，编译器读取磁盘，不检查未保存的编辑内容；只要任一打开的本地文件与磁盘内容不同，检查会跳过。文件修改会使已有诊断失效；未启用文件监听时，需再次保存才会重新检查。诊断位置由编译器文本输出推算，为零长度，且不是完整源范围。编译器启动失败、超时或输出过大时会在客户端日志中说明。编译器给出了文件但行列无法映射到当前文本（行号越界、列落在多字节字符中间或 CRLF 之间）时，诊断仍会下发，位置退化为文件开头（`0:0`），消息末尾标注「position not located」并附编译器原始行号与字节列，同时日志仍保留一条警告便于排错。

客户端支持动态注册文件监听时，服务器会注册 `**/*.jik` 监听；收到工作区文件变更后重新检查已知入口，而不是仅清除诊断，因此编辑器自己的保存通知即使晚于保存事件到达，也不会取消有效检查。未注册监听（客户端不支持或注册失败）时，外部修改只能由下一次保存发现；变更的未打开依赖文件也不会因此获得可靠校验。

检查前后会比较已打开文件的内容、文件身份及修改时间，并在发布前再次读取；工作区事件是否视为自身保存的回声按内容判定，不依赖时间戳。诊断路径通过规范路径（Unix 上也通过设备号和 inode）匹配已打开文件。快照仍不能保证检测所有外部修改：未打开的依赖文件不在快照内，文件可能在最后一次检查后被修改，文件系统时间戳精度也可能不足。请以编译器输出为准。

上述限制中，只有编译器暴露其读取的依赖及其版本后，未打开依赖的校验才能可靠解决；最终复查与发布之间的竞态需要隔离的不可变输入快照。这两项都需要编译器侧协作，不在本服务器范围内。

目前尚不提供补全、跳转或语义索引。使用 `cargo test` 运行测试；`tests/real_compiler.rs` 中的契约测试会调用真实编译器，路径默认为 `../jik/jik`，可用 `JIK_LSP_TEST_COMPILER` 覆盖，找不到时跳过。

GitHub Actions 在 `.github/workflows/ci.yml` 中执行 `cargo fmt --all --check`、`cargo clippy --all-targets -- -D warnings` 和 Linux/macOS/Windows 三平台的 `cargo test`；push 到 `main` 与所有 PR 都会触发。CI 环境没有 `../jik/jik`，因此只运行假编译器用例。

真实编译器的行为由契约测试固定下来：诊断列号是 UTF-8 字节列（服务器负责换算为 UTF-16 位置，含中文时字节列与字符列会不同）；解析错误逐条报告，但语义分析在同一模块遇到第一个未定义符号即停止，因此一个保存周期内只可能看到一条语义错误。
