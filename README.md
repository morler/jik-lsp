# jik-lsp

基于 Rust 和 `tower-lsp` 的 Jik 语言服务器，目前支持完整文档同步和保存后诊断。

```sh
cargo build --release
```

启动 `target/release/jik-lsp`，使用标准输入/输出进行 LSP 通信。在编辑器的语言服务器配置中将 `.jik` 文件关联到该程序；初始化选项示例：

```json
{
  "jikPath": "/absolute/path/to/jik",
  "entryPath": "/absolute/path/to/project/main.jik"
}
```

`jikPath` 可省略，默认使用 PATH 中的 `jik`。`entryPath` 可省略，默认检查保存的文件；配置时必须使用绝对路径。`jik check` 要求有效的程序入口，直接检查独立模块可能报告缺少 `main`。编译器需要自身安装目录中的 `jiklib`，并遵循其 `JIK_PKG_PATH` 设置。

诊断只在保存后运行，编译器读取磁盘，不检查未保存的编辑内容；只要任一打开的本地文件与磁盘内容不同，检查会跳过。文件修改会使已有诊断失效；未启用文件监听时，需再次保存才会重新检查。诊断位置由编译器文本输出推算，为零长度，且不是完整源范围。编译器启动失败、超时、输出过大或无法定位的消息会写入客户端日志。

客户端支持动态注册文件监听时，服务器会注册 `**/*.jik` 监听；收到工作区文件变更后重新检查已知入口，而不是仅清除诊断，因此编辑器自己的保存通知即使晚于保存事件到达，也不会取消有效检查。未注册监听（客户端不支持或注册失败）时，外部修改只能由下一次保存发现；变更的未打开依赖文件也不会因此获得可靠校验。

检查前后会比较已打开文件的内容、文件身份及修改时间，并在发布前再次检查；诊断路径通过规范路径（Unix 上也通过设备号和 inode）匹配已打开文件。快照仍不能保证检测所有外部修改：未打开的依赖文件不在快照内，文件可能在最后一次检查后被修改，文件系统时间戳精度也可能不足。请以编译器输出为准。

目前尚不提供补全、跳转或语义索引。使用 `cargo test` 运行测试；真实编译器测试在 `../jik/jik` 存在时运行，否则跳过。
